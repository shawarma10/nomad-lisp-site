    Language Guide

    An introduction to the syntax and concepts of Nomad Lisp.

    Nomad Lisp is a Lisp dialect: programs are made of S-expressions that are homoiconic (code is data). It is not a particularly beginner-friendly language and assumes familiarity with immutability, higher-order functions, homoiconicity and recursion. Its standard library is deliberately small.

    Syntax

    All functions are applied in the same way:

    # This is a comment
(<function expression> <function arguments...>)

    Comments begin with # and extend to the end of the line. The literals of the language are numbers (42, -3.5), strings ("text"), the booleans true and false, and unit.

    Everything is a function

    Constructs that would be special syntax in other languages, such as if, let or lambda, are ordinary functions in Nomad Lisp. This is possible because native functions receive their arguments as raw, unevaluated S-expressions and decide for themselves what to evaluate.

    As a consequence, +, -, *, / and even if and let are values that may be passed to other functions.

    Expressions and unit

    Nomad Lisp is expression-oriented: everything evaluates to a value. There is no void as in Java; instead, there is unit, a type with a single value which indicates that there is no meaningful result. Those familiar with Rust or OCaml will recognize it.

    unit distinguishes procedures from functions that return a value, and is also returned by car and cdr to signal an empty list.

    Because if is an expression, its result can be used directly:

    (println
  (if true
    "True!"
    "False!"))

    Variables and functions

    (let x 10)
(let y 20)
(println (+ x y)) # 30

(letfun greet (name) (println "Hello, " name))
(greet "John Doe") # Hello, John Doe

    See Variables and Functions.

    Sequencing

    Bodies and branches accept a single expression. Use do to evaluate several expressions in order; it returns the value of the last one:

    (letfun count (start end)
  (if (< end start)
    (println "done!")
    (do
      (println start)
      (count (+ start 1) end))))

    Exceptions

    Errors are reported as exceptions. They can be thrown with throw and handled with try:

    (let x "123abc")
(try
  (string_to_num x)
  (println "Couldn't parse " x " to a number!"))

    See Control Flow.
