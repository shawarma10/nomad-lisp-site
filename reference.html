    Implementer's Reference

    An informal specification for implementations of Nomad Lisp.

    This document is an informal reference that defines what Nomad Lisp is, for the benefit of those who wish to write their own implementation.

    Design goals

    Nomad Lisp is designed to be tiny, even more so than most embeddable languages. An implementation usually consists of:

    • A lexer that turns source code into tokens
    • A parser that constructs S-expressions from tokens
    • An evaluator that knows how to call callable objects (lambdas, macros and native functions) and resolve atoms to values
    • A prelude for common programming tasks
    • A strong embedding API for the host language

    The prelude

    The prelude of an implementation should generally include:

    • Constructs for declaring variables, functions, macros and lexical scopes, such as let, letfun, letmac and scoped
    • Conditionals, such as if, =, >, <, >= and <=
    • Arithmetic operations, such as +, -, *, / and mod
    • Functions for printing to standard output and reading from standard input, such as print, println and readln
    • Exception handling with try and throw
    • Explicit mutation with mut and record_mut

    The prelude is not part of the language's grammar. It is a collection of native callbacks, and these callbacks receive syntax (S-expressions), not evaluated values. If callbacks received eagerly evaluated arguments, constructs such as if would not be possible.

    The embedding API

    Because callbacks receive S-expressions, the embedding API must give its users access to the syntax tree, while offering convenience functions such as get_string for the common case in which lazy evaluation is not needed. An example using romad, the Rust implementation:

    use romad::natives_util::get_string;
use romad::{Interpreter, NomadError, Value};

fn main() -> Result<(), NomadError> {
    let interp = Interpreter::new(); // Create a new interpreter
    interp.register_native("log", |args, env| {
        // Check argument length
        if args.len() != 1 {
            return Err(NomadError::eval(format!(
                "Error in call to log: Expected one argument, got {}",
                args.len()
            )));
        }

        // We expect a string as the argument, anything else is an error.
        let log_string = get_string(&args[0], env)?;

        eprintln!("{log_string}");
        Ok(Value::Unit)
    })?;

    interp.do_string("(log \"Romad interpreter running!\")")?;
    Ok(())
}

    The type system

    The types of Nomad Lisp are:

    • string
    • number (best implemented as a 64-bit floating point number)
    • bool
    • list
    • record
    • function (lambdas written in Nomad Lisp itself)
    • native functions
    • macro
    • unit (the terminal type, similar to null or nil in other languages)

    Macros

    Macros are kept deliberately simple. They are templates into which syntax is injected upon invocation:

    (letmac when (cond body) if cond body unit)
(when true (println "Hello World!"))

    This invocation should expand into:

    (if true (println "Hello World!") unit)

    Implementations must also replace macro parameters that appear nested inside lists.
